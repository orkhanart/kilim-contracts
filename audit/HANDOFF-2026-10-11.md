# Kilim contracts: handoff for an independent security audit

Prepared 11 October 2026 for the audit that [AUDIT.md](../AUDIT.md) lists as launch blocker K-08. Contact: Orkhan (orkhanart.eth), hey@orkhan.art.

**Status.** Nothing is deployed. Claude instances wrote the code, and every review so far was also done by Claude instances. No human has audited it. The internal record ([AUDIT.md](../AUDIT.md)) marks it "Not approved for a real-money launch". The contracts have no admin role and cannot be upgraded or paused, so mistakes cannot be fixed after deployment. Your findings decide what changes before the freeze.

## 1. The system

The system is a single English auction in native ETH on Ethereum mainnet, plus two ERC-721 contracts that only the auction can mint into.

| Contract | File | Role |
| --- | --- | --- |
| `EnglishAuction` (abstract) | `src/auction/EnglishAuction.sol` | Registration of 100 wallets before bidding opens (`register`, or `registerFor` with an EIP-712 / ERC-1271 signature). Payable bids where `msg.value` must equal the bid. thirdweb's `_isNewWinningBid` predicate. The outbid bidder is refunded automatically inside the next bid, with a pull fallback. The clock starts at the first bid, and late bids extend it with no limit. Settlement is permissionless. The treasury withdraws the proceeds. Apache-2.0, adapted from thirdweb. |
| `KilimAuction` | `src/KilimAuction.sol` | Extends `EnglishAuction`. Every accepted bid earns motif credits, one per 0.001 ETH, which reserve the next token ids. Outbid bidders keep their credits. Bidders claim with `claimMotifs`, up to 64 per call. At settlement the 1/1 is delivered to the winner; if that fails, the winner calls `claimPrize(to)`. `highestBidMotifs()` returns the ids the winning bid reserved. |
| `KilimMotifs` ("Motif Bazaar", `MOTIF`) | `src/KilimMotifs.sol` | Up to `motifCap` tokens with ids `1..motifCap`. Each token shows one of 1,024 motifs: `motifOf(id) = keccak256(abi.encode(deploymentChainId, address(this), id)) % 1024 + 1`. The grids and names are stored in SSTORE2 chunks, and the constructor checks them by keccak. The SVG `tokenURI` is drawn on-chain. Only the owner can burn, and a burned id can never be minted again (bitmap). The minter is the auction and is immutable. |
| `KilimOneOfOne` ("The Unwoven Kilim", `UNWOVEN`) | `src/KilimOneOfOne.sol` | One token, id 1, minted once by the auction. The page is stored in SSTORE2 chunks as three sections (PREFIX, HEAD, TAIL), each checked by keccak. `tokenURI(1)` builds about 1.07 MB in a single memory buffer, in assembly, and reads the motif grids live from `KilimMotifs.grids()`. |

The two token contracts are deployed first. Each names the auction's address as its minter, predicted from the deployer's nonce n + 2. The auction's constructor checks that both name it as minter and that the 1/1 reads this motif contract.

None of the contracts has an owner, admin, pause, upgrade, metadata setter, rescue function, `receive` or fallback. Every parameter is set by a constructor argument or a constant. Royalties are a fixed 5% (ERC-2981). A fifth contract, the weaver ("Kilim Bazaar", which will burn motifs), is not built and is not in scope.

Specifications: [docs/CONTRACTS.md](../docs/CONTRACTS.md) (the design), [docs/NATIVE-ETH.md](../docs/NATIVE-ETH.md) (auction behaviour), [docs/STORAGE.md](../docs/STORAGE.md) (chunks, hash chain, `tokenURI` assembly, deployment refusals), [REUSE.md](../REUSE.md) (thirdweb and OpenZeppelin provenance).

## 3. Build and test

## 5. Trust model and roles

- **One key holds three roles.** orkhanart.eth deploys the contracts, is the auction's `treasury` and is the `royaltyReceiver` of both token contracts. It is a single-key personal wallet, not a multisig.
  - What the key can do: call `withdrawProceeds(to)` once after settlement.
  - What it cannot do: register or bid (`TreasuryCannotBid`), mint, move tokens, or change any parameter.
  - If the key is lost, the proceeds stay in the auction for ever. If it is compromised, the attacker takes the proceeds and every future ERC-2981 royalty (the same immutable address is `royaltyReceiver` of both token contracts); before deployment the same key could also spend the published nonce. It can do nothing else to the auction or the tokens.
- **The minter.** Each token contract's `minter` is the auction, immutable. Only the auction mints: motifs through `claimMotifs`, the 1/1 through settlement or `claimPrize`.
- **Self-calls.** `payOutbidRefund` and `deliverPrize` are external so that a failure can be caught. They accept only `msg.sender == address(this)`. `deliverPrize` has no `settled` check of its own (F-21); it is reached only from `_afterSettle`.
- **The store.** Any funded wallet may send the chunks through the CREATE2 deployer `0x4e59b44847b379578588920cA78FbF26c0B4956C` with salt 0. A chunk's address depends only on its bytes, and the constructors hash the chunk contents. The deployer must not send them once its nonce is published.
- **The deployer's current state.** On mainnet the deployer currently carries an EIP-7702 delegation: code `0xef0100` followed by `63c0c19a282a1b52b07dd5a65b58948a07dae32b`, MetaMask's delegator, at nonce 1,566 (read again for this handoff). It has no delegation on Sepolia. The deploy script refuses a deployer with code. Switching back to a standard account is one transaction and spends nonce 1,566, so the first creation will be at nonce 1,567 if nothing else is sent.
- **Off-chain components** (the site and the optional relayer) are trusted only for display and convenience. No contract path depends on them.

## 6. Accepted design risks (artist's decisions)

These are deliberate design choices. Please weigh them, but do not report them as new findings unless the analysis behind them is wrong.

| ID | Risk | Decision |
| --- | --- | --- |
| K-01 / F-04 | Refund-and-keep rewards. An outbid bidder gets all its ETH back and keeps every credit. One wallet outbidding itself along the minimum steps reserves all 1,000,000 motifs in 93 bids, ending at a top bid of 93.862 ETH, for the cost of gas if it is then outbid. A self-ladder to 1.06 ETH earns 11,351 motifs, against 1,060 for one honest bid. F-07, a ladder placed in front of a pending jump bid, follows from this. | Accepted 18 and 25 September and 9 October 2026 as the intended incentive. Non-refundable purchases, increment-only rewards and winner-only rewards were offered and declined. To be disclosed plainly. |
| F-03 (with F-11) | Registration capture. Registration checks a balance, not a person. The same 0.01 ETH can pass through 100 addresses in one transaction (7,772,061 gas) and place the opening bid. `registered` confers nothing. | Accepted 9 October. |
| F-10 | No fallback date. Bidding never opens below 100 registrations, and with no bids `settle()` reverts `NoBids` for ever. | Accepted 9 October. The artist promotes until the count is reached. |
| K-02 | Public, deterministic motif layout. `motifOf(id)` depends on the chain id recorded at deployment, the contract address and the id. Each bid reserves the next ids. Rarity is a public race, and a bid landing first moves later ranges (`expectedFirstMotifId` lets a bidder revert instead). The deployer's choice of key and nonce fixes the layout. | No VRF, by owner decision. To be disclosed. Publishing the nonce in advance does not prove the layout was not chosen. |
| K-07 / FA-07 | The seller's other wallets. The treasury cannot bid, but other wallets of the artist's are undetectable. If such a wallet laddered all the motifs and won, the winning bid would return to the artist, so it would cost only gas. | Disclosed. The artist commits not to bid from any wallet (11 October). |
| K-05 | Timestamp reliance. Registration opens, the clock starts and extensions are measured by `block.timestamp`. There is no absolute end, and no restart if an outage hits near the close. Timestamps are never used as entropy. | Documented behaviour. Slither's timestamp findings are kept, not suppressed. |
| K-06 (with F-19) | Forced ETH. With no `receive` or fallback, ETH forced in (for example by selfdestruct) is never counted and cannot be recovered. A refund owed to a contract that can neither receive ETH nor call `withdrawRefund` is also locked. | Deliberate: no administrative path to the escrow. |
| The Master rule | The weaver (not built) prices its top rank at the winning bid counted in motifs, read from `highestBid`. It reads the winner's own ids from `highestBidMotifs()` (FA-08). If the pool ran short, the winning bid earned fewer motifs than its price, or none. | Decided 11 October: the rule stays. The winner then gathers the rest like anyone else. The getter is in scope; the rule is not. |
| FA-06 | `deliverPrizeToWinner()` removed. It was an open re-delivery added on 10 October (V-15), which let a third party push the 1/1 into a winning contract before the winner could redirect it. Since 11 October only the winner can claim, with `claimPrize(to)`. Consequence: a winning contract that cannot make calls, and whose receiver needs more than the 500,000 gas, can never get the 1/1. | Decided 11 October ("let the winner press"). Bidders are told to use a wallet that can send transactions later. |

Also recorded and accepted: F-06 (an outbid contract can make each rival's bid cost about 140,000 to 180,000 more gas, because `REFUND_GAS` is generous); F-22 (registration signatures have no upper bound on `deadline` and cannot be revoked); F-23 (once the count is 100, any non-treasury wallet can bid, registered or not); F-24 (a bid carries no deadline).

## 7. Where we most want independent eyes

Most important first.

1. **`KilimOneOfOne.tokenURI` assembly** (`src/KilimOneOfOne.sol` lines 120–330).
   - It writes the whole answer in one buffer from `mload(0x40)` and never moves the free-memory pointer. It ends in `return` from assembly, so it must never be called internally.
   - It uses scratch memory 0x00–0x3f for the `grids()` call and then for the base64 alphabet.
   - HEAD is placed at `raw = piece + m/3` so that the in-place base64 encoder never overtakes unread bytes.
   - The grids are expanded to hex forward from the second half of the hex room.
   - Both encoders are word-at-a-time bit tricks (`hexHalf`, `base64Block`); the comment claims "no lane borrows".
   - The tail loop `mload`s a 32-byte word at each 3-byte group and keeps its top 3 bytes, so for the last group it reads up to 29 bytes past the end of the input.
   - The total length is computed from the chunks' live `extcodesize`, and an exact-end check precedes the `return`.
   - What we would like checked: overrun or aliasing, lane carries, a `grids()` answer of the wrong size (`GridsUnavailable`), and whether any chunk layout or `HEAD` length passes the constructor but breaks the arithmetic.
   - Existing evidence: differential fuzzing against `abi.encodePacked` plus OpenZeppelin `Base64` (`test/KilimOneOfOne.t.sol`, `test/review/OneOfOneEncoders.t.sol`, `OneOfOneGridsSource.t.sol`). The mutation campaign did not mutate the encoders.
   - Lower priority in the same contract family: the chunk readers in `KilimMotifs` (`grid`, `motifName`, `_grids`, `_checkNames`) and the SVG run encoder.
2. **`EnglishAuction`'s refund gas floor and deferred refunds** (`_refundOutbid` lines 238–251, `payOutbidRefund`, `withdrawRefund`; constants at lines 21 and 26).
   - The design claim (F-01): with `gasleft() >= REFUND_GAS + REFUND_GAS/63 + 300,000` checked before the capped self-call, the gas a bid needs never depends on the outbid wallet's code. The leader therefore cannot make a rival's correctly estimated bid run out of gas.
   - The deferred path must always fit in what is left, including return-data bombs and EIP-7702 wallets that gain code after bidding.
   - The solvency invariant to check: `balance >= liabilities() = refundLiability + (settled ? proceedsDue : highestBid)`.
   - The same pattern guards settlement: `_afterSettle`'s floor of `PRIZE_GAS + PRIZE_GAS/63 + 50,000`, and the `try this.deliverPrize{gas: PRIZE_GAS}()` that falls back to `claimPrize`.
3. **The claim range accounting** (`KilimAuction._bid` lines 115–137, `_claim` 166–193, `unclaimedMotifRanges`; `KilimMotifs.mintMotifs` 106–125 and `burn`).
   - Each rewarding bid pushes a `CreditRange` and advances `motifsAllocated`. Claims walk the ranges oldest-first from a per-bidder cursor and mint each range in a separate external call.
   - Please confirm that every id in `1..motifCap` is reserved at most once and minted at most once, even after a burn; that `motifCredits` equals the sum of the remaining ranges; that a claim reverts whole when a later range's receiver refuses; that `highestBidMotifs()` always equals the winning `BidPlaced`; and that the uint128 narrowing is safe.
4. **The deploy script's refusals and its CREATE2 and nonce prediction** (`script/DeployKilim.s.sol`: `deployStore` 245, `loadStore` 292, `_loadSection` 372, `deployContracts` 447, `deployAuction` 495, `_requirePlainDeployer` 559, `_requireNothingPending`/`_pendingNonce` 567–581, `_predict`/`_create2` 920–945).
   - The minter of both token contracts is `computeCreateAddress(deployer, n + 2)`, so everything rests on the three creations landing at n, n + 1 and n + 2.
   - The script checks the latest and the pending nonce, refuses a deployer with code, refuses a store sent by the deployer once its nonce is published, and completes only a dropped (never mined) third creation (`runAuction`, FA-04).
   - Areas to check: any sequence (mempool replacement, EIP-7702, forge `--slow`/`--resume` behaviour) that spends n + 2 without the script noticing; the CREATE2 deployer being assumed rather than checked (forge's simulation supplies it); config integers narrowed to uint64/uint16 without a range check (F-26); and whether `_measured` (FA-05, conservative) can pass a creation that would really exceed the policy.
   - `runAuction()` and `--resume` have never been run against a live node.
5. **The Glamsterdam gas assumptions** (`PRIZE_GAS`, `REFUND_GAS`, `DEFERRED_REFUND_RESERVE`). Sepolia has run Glamsterdam since 6 October 2026. Mainnet has no date. EIP-8037 stays in Last Call until 1 November 2026, so its prices are not final.
   - Deferred refund: projected at 225,840 gas, against the 300,000 reserve.
   - Prize delivery: measured cold as a mainnet `settle()` meets it, a winner's receiver may use 387,122 of the 500,000 today, and a projected 34,542 after the repricing (at most 22,334 for a Safe's handler). A receiver that writes one new slot will not fit and must use `claimPrize`.
   - Deployment: under EIP-8037 a full chunk needs at least 38,626,249 gas, and the three contracts about 18.6M, 24.9M and 18.1M (estimated on the store of the 283 KB PNG still; the 1/1's figure is lower with the WebP still, since its Cancun creation fell from 8,087,087 to 6,601,234). The plan is therefore to deploy before mainnet forks. On Sepolia, broadcast with `--skip-simulation --gas-estimate-multiplier 120` (checklists/2-deploy.md).
   - Is a fixed `PRIZE_GAS` of 500,000 the right trade, and can either floor become unsatisfiable or insufficient under the final prices?
6. **The reused thirdweb predicate** (`_isNewWinningBid`, lines 261–275). It is kept unchanged from thirdweb `contracts` commit `46e69070978c23b9533edb381e838a5dddf7ed9d`, `EnglishAuctionsLogic.sol` (SHA-256 `5c3e0e3d331c38b1f9487230002f0f68b8972d10232ad435338229549995f52e`, the 0xMacro A-15 reference). `verify:upstream` checks it.
   - Our changes around it: amounts are bounded to uint128 before the call, so `diff * 10,000` cannot overflow; bids must be whole 0.001 ETH units; and `minimumBid()` rounds up with `mulDiv(..., Ceil)` and `ceilDiv`.
   - Please confirm that `minimumBid()` is always accepted and is the smallest accepted whole-unit bid for every `incrementBps` in 1..10,000.
   - The upstream audit does not cover the escrow, registration or reward code around the predicate (REUSE.md).

## 9. Known open items

- **K-08**, this audit, on the frozen commit.
- **The deployer wallet.** It must switch back from the EIP-7702 delegation (one transaction; sent by the wallet itself it uses two nonces, so expect 1,568), confirm `eth_getCode` returns `0x`, and then publish the nonce it reads.
